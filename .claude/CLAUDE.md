## Commit Policy

After making any meaningful changes to files, commit them promptly with a descriptive commit message. Do not wait to be asked — batch related changes into logical commits and push them to the remote if on a feature branch.

- **When to commit**: After completing a discrete unit of work — adding a feature, fixing a bug, refactoring a component, or making configuration changes.
- **Commit messages**: Use concise, imperative-style messages that describe what was changed and why.
- **Branch policy**: If working on the default branch, create a feature branch first before committing.
- **Do NOT commit**: Unrelated changes in the same commit — keep commits focused and atomic.
