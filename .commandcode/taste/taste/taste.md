# Taste
- Runs Python tooling through `uv`: tests via `uv run pytest -q`, linting via `uv run ruff check` (with `--fix` applied only to touched files), type checking via `uv run pyrefly check`. Confidence: 0.9
- Scopes lint/type fixes to files authored or touched in the current change; leaves pre-existing errors in legacy/unrelated files alone instead of attempting repo-wide cleanups. Confidence: 0.85
- Verifies work end-to-end before declaring completion: full test suite, both static checks (ruff + pyrefly), then live CLI smoke tests of any new command surface; explicitly reports what couldn't be verified locally (e.g., missing cross-compilation toolchains); when a static checker reports many pre-existing errors, stashes the working tree to diff the baseline count and prove the change introduces none. Runs every CI-gated job locally in sequence with the workflow's exact commands (cargo test --manifest-path, uv-run pytest, ruff check) before declaring the build green. Confidence: 0.9
- Re-reads the affected region of a file whenever an edit result looks off before continuing to build on it. Confidence: 0.75
- Develops on Windows: uses `findstr` pipelines for log filtering, `%LOCALAPPDATA%` cache locations, `D:\Programming\...` project roots, and PowerShell (`Move-Item`, `Remove-Item`, `Get-ChildItem`, `Select-String`) for bulk file inspection/manipulation instead of bash syntax. Confidence: 0.85
- Satisfies the type checker with genuine narrowing (`isinstance` guards, `getattr(...)` fallbacks) rather than `type: ignore` suppressions or unchecked casts. Confidence: 0.75
- Vendors third-party source into the repo when registry packages are unusable placeholders (e.g., ruff's internal crates): downloads a pinned upstream tag/commit, strips test fixtures/snapshots from the copy, records provenance per-crate via `[package.metadata.*]` (vendored-from/vendored-ref), and ships a vendor README listing local modifications plus an update procedure. Confidence: 0.8
- For multi-step or heredoc-style shell work, writes small Python scripts to the session scratchpad and runs them rather than wrestling with cmd-incompatible one-liners; reuses this pattern to isolate failures — directly exercising internals with constructed inputs (e.g., `_resolve_targets`), dumping graph edges/node trees, syntax-checking generated JS via `node --check` — then deletes the scratch scripts when done. Confidence: 0.75
- When the user explicitly mandates a specific library/tool ("use X, make that what you need to use"), adopts it exactly as named — restructuring build layout if needed (e.g., vendoring ruff's AST crates into a new cargo workspace) rather than substituting an alternative. Confidence: 0.75
- Prefers minimal-diff solutions: adapts configuration to fit existing code (pinning a crate to edition 2021 with an explanatory comment) instead of mass-migrating source, and drops unused optional features/deps from vendored code rather than pulling in more of it. Confidence: 0.7
- Audits delivered work mid-stream and pushes for extra test coverage of remaining gaps: import/dependency-detection features should be tested not only for detecting imports but also for validating symbol-level import and usage (e.g., Cython/compiled-extension modules). Expect this bar and cover such cases proactively. Confidence: 0.55
 Checks CI workflow config to see which gates actually block merges (here: pytest + ruff, not pyrefly), fixes enforced-gate findings on touched files, and treats non-gated checker noise as informational after proving none of it originates in the new code. Confidence: 0.6
- Before building a mechanism, greps for hooks/contracts the codebase already declares but never fires (e.g., plugin `module_parsed`/`transform_ast` runner methods, a promised `"ast"` key in module info) and implements those exact contracts rather than inventing parallel APIs. Confidence: 0.6
- After editing pyo3/Rust code, forces a native extension rebuild before trusting Python tests (`uv sync --all-groups`; if it reports up-to-date without recompiling, `uv run --no-sync maturin develop --release`), then runs tests with `--no-sync` against the fresh build. Confidence: 0.7
- On test failures, sorts bad expectations from real bugs and fixes the guilty side honestly (rewrote mistaken test expectations, fixed a double-scanning bug), then prefers structural root-cause fixes — e.g., reordering analysis phases so nodes register with correct types up front; when fetched graph nodes proved to be Rust-backed clones whose mutations silently vanished, added write-through mutators (`set_node_content`/`set_node_required` via `get_node_mut`) at the pyo3 layer instead of patching around clone-on-read in Python. Confidence: 0.75
- Distinguishes "stub that proves the path exists" from "real implementation that actually does the work": when a feature has a working pipeline behind it but the user-facing side is `console.log("WASM app: ...")` and the assembler drops the glue JS that the wasm needs to instantiate, treat that as incomplete and replace it with a real self-contained bundle (proper glue detection, NODEFS preopens, validated `node --check`). Confidence: 0.8
- Treats new-message follow-up prompts ("see what more you can improve?") as license to do a real survey of the codebase: greps for dead/unused code, declared-but-unwired contracts, hand-rolled reimplementations, and hidden bugs, then prioritizes by leverage (dead-code paths to live features first, then narrow correctness/perf wins); each improvement gets its own todo entry and end-to-end tests rather than a single mega-edit. Confidence: 0.8
- When the user's design is "X should be evaluated by plugins downstream," implements the full pipeline: parse phase that populates a compiler-level AST cache, a handoff phase that fires plugin hooks (`module_parsed` read-only, `transform_ast` mutating) over the live trees, a sync phase that unparses transformed trees back into node content via a write-through mutator (so plugins don't have to deal with Rust's clone-on-read), and cache exposure (`get_module_ast`/`set_module_ast` + `module_asts`/`module_asts_snapshot` on the context). The plumbing matches the order: hooks fire *before* downstream consumers (tree shaking, VFS emit). Confidence: 0.7
- Plays the long game when spec promises a feature but no tests cover it: a 500-line `ASTPruner` plus `SymbolReachabilityAnalyzer` sitting unused in the optimizer, with the compiler only doing module-level reachability, is high-leverage. Wires it into the pipeline, then *unwinds the real bugs that the wiring reveals* (clone-on-read Rust nodes, property-that-returns-fresh-copy silently dropping writes, missing per-symbol root seeding because the analyzer only knows about symbol-level reachability). Fixes the API surface as well as the call sites. Confidence: 0.7
- Builds end-to-end tests shaped like real projects (packages with relative imports, stdlib usage, resource files, dynamic Cython fallbacks) — and runs the resulting VFS under plain CPython to assert behavior matches the source. These tests surface pre-existing bugs (relative `__init__.py` imports producing phantom `pkg..sub` nodes; resource discovery only logging without creating graph nodes; package `__init__` files not signaling "I'm a package" to the relative-import resolver) that targeted unit tests miss. Confidence: 0.75
- When `findstr` pipelines don't show the log line that should be there, falls back to a different log-capture path (Python `logging.basicConfig(level=INFO)` in scratch scripts, pytest `caplog` with explicit logger/set_level, `--log-cli-level=DEBUG`) rather than trusting the absence of output. Confidence: 0.7
- The user's mental model of "AST" is "the AST travels with the node": when wiring plugins to consume ASTs, ensure `PluginContext.get_module_info()["ast"]` returns the live tree, the module_asts dict is a live reference (not a property that copies), and the sync-to-content pass runs at the right point in the pipeline (after plugin transforms, before tree shaking and VFS emit). When asked to add this, ships the full chain — parse, hand-off, transform sync, and downstream consumption — not just the cache. Confidence: 0.7
- When a Rust pyclass enum's `__str__` returns `"NodeType::python_module"` but the Python wrapper compares against the bare string `"python_module"`, normalizes at the wrapper boundary (a `node_type` property that strips the `NodeType::` prefix) rather than asking callers to learn the prefixed form. Same for setters — accept either form and map to the Rust enum. Confidence: 0.65
- Runs the full test suite + ruff + cargo at the end of each improvement wave, with all three gates in the same `shell_command` invocation, so the green-light verification is a single observation rather than a sequence of hopeful probes. Confidence: 0.7
- For multi-prong improvements, the testing strategy is: write the test for the new behavior first, run it (often failing), debug the failure into either a real bug or a wrong test premise, fix whichever side is guilty, then add structural tests (orphan-module, no-op plugin, third-party imports, end-to-end VFS run) so the next refactor can't silently re-break the invariant. Confidence: 0.65
- When ruff/pyrefly/etc. complain about complexity (C901) on a function that can't be made simpler without losing the single mental model, splits into named helpers (`_collect_plugins`, `_run_plugin_chain`, `_summary_header_lines`, `_collect_kept_names`, `_add_top_level_renames`, `_add_import_alias_renames`, `_resolve_via_plugin`, `_resolve_absolute`, `_resolve_relative`) rather than the terse two-letter name. The top-level orchestrator becomes a short sequence of named steps; each helper is independently understandable. Confidence: 0.6
- After a major improvement wave, finishes with a structured markdown table mapping each audit item to its status and a one-line "what changed" summary, plus a clear "caveats / not done" section listing what was deliberately left out. Tables are the preferred format for closing reports, not prose. Confidence: 0.7
- When implementing a spec-promised feature that's missing the user-facing side (e.g., a 500-line internal pass with no compile flag, or a config key that's never read), scaffolds the full UX in one wave: the config field in ForgerConfig + TypedDict + defineConfig parser, the auto-injection in the compiler, the end-to-end test that proves the user can actually opt in. Half-implementations (config exists but no parser, parser exists but compiler ignores it) don't count. Confidence: 0.65
- "Continue what's missing?" / "see what else needs work" / similar prompts from the user are an explicit signal to do a structured spec-vs-implementation audit (subagent or self-review), list gaps with severity, pick the high-leverage ones, and ship them — not a request for one more small fix. Each picked gap gets its own todo entry, its own test, and its own summary line. Confidence: 0.7
- When picking which gaps to close, prefers small, interlocking clusters that compose into a single coherent story (e.g., "structured errors + virtual modules + live get_module_info + e2e plugin tests + minifier __all__ tests" — together they produce a working framework-plugin story) over a grab-bag of unrelated fixes. Names the unifying thread out loud before listing the todos so the rationale is visible. Confidence: 0.65
- Categorizes plugin hooks by failure semantics: hooks whose silent failure would corrupt downstream state (e.g., `resolve_id`, `load` — wrong results poison the graph) must raise typed exceptions that abort the build; transform-style hooks keep log-and-continue. Documents the split in a `STRICT_HOOKS` frozenset next to the error hierarchy. State the rationale out loud in code comments (why *this* hook is strict, not the other) so future maintainers don't flatten the distinction. Confidence: 0.7
- Builds exception hierarchies that carry structured metadata on the exception object itself, not just in the message: `PluginError(..., plugin_name=..., hook=..., module_id=..., source_file=..., cause=...)` with an `as_dict()` for diagnostic/JSON consumption, and a custom `__str__` that renders the metadata so tracebacks and `repr(exc)` are useful without callers having to know the attribute layout. Distinguishes separate subclasses (`CompilerError` / `PluginError` / `SourceError` / `ResourceError`) so callers can branch on `isinstance` rather than parsing the message. Confidence: 0.65
